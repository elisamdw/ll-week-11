# Plugins, skills and examples

## Plugins

Plugins are trusted local code with no sandbox: a backend module runs inside the app's Node server, a frontend module in the page (`docs/plugin-authoring.md`, `docs/plugin-architecture.md`). Every plugin, core or community, starts disabled (`docs/plugin-architecture.md`). A community plugin is a built `dist/` folder (manifest, optional frontend, backend, styles) under the learning-data folder, with its own `data/` beside it; the app never runs npm for it. Settings can download an "authoring skill" bundle to hand to a coding agent.

What a plugin can add (`docs/plugin-authoring.md`, "Choose the extension point"; the contracts in `docs/plugin-*-contract.md`):

- views, actions and settings pages; host widgets (buttons, badges, Markdown, a tree, a picker of graph material);
- extra instructions and tools for the three agents, added to theirs, never replacing them;
- new question types for teaching, with an optional grading hook whose result the teacher reads (the host gives no score);
- new practice problem types (a statement, a mode, targets, a committed solution), which the learner can submit many times; only the native `conclude` closes a problem;
- interceptors on what the learner sends; renderers for code blocks and tool results; read-only access to sessions and the graph; model calls through the learner's providers; managed agent conversations; background workers.

## The shipped plugins

Four are listed as core in `core-plugins.json`; a fifth is a developer gallery.

- **Flashcards** (`plugins/flashcards/`, `docs/flashcards-vision.md`, `docs/flashcards-implementation-plan.md`): spaced repetition with the FSRS-6 scheduler, one schedule per proposition (each proposition can have several cue cards). Cards come from graph propositions, from a file (generated by a cheap model), or by hand. Review is think, reveal, then rate yourself Again, Hard, Good or Easy: no typing, no model, no AI grading. Defaults: 90% target retention, 20 new propositions a day per deck. A dashboard shows new, learning and review counts, what is due over the next week, and two weeks of ratings. Nothing is written back to the graph.
- **Coding questions** (`plugins/coding-questions/`): an editor with starter code; tests the teacher wrote run on the learner's machine on each submission (30-second limit) and show passed, failed or could not run, explicitly not a score.
- **Drawing pad** (`plugins/drawing-pad/`): a pen canvas over the current question; the drawing goes with the next answer as an image.
- **Rich code blocks** (`plugins/rich-code-blocks/`): renders chemistry (SMILES), music notation (ABC) and TikZ diagrams as images, and tells the agents they can use them.
- **UI showcase** (`plugins/ui-showcase/`): a gallery of the plugin widgets for developers.

`examples/plugins/` has three small templates: a hello-world view, a managed agent that can ask the learner questions and keep notes, and a teaching extension with a background worker.

## Skills for outside agents

`skills/learnharness/SKILL.md` lets an outside agent such as Claude Code read a learner's LearnHarness data, strictly read-only, with standard-library Python scripts (`scripts/sessions.py` for transcripts with answers, confidence and thinking; `scripts/graph.py` for propositions and chains). Its guidance is worth borrowing: sessions are the evidence of understanding, the graph is a map of what was taught; teacher prose and graph content are model-written and can be wrong; self-reported confidence is not a score, and a missing value is not zero. `skills/learnharness/references/data-format.md` documents the on-disk layout. `skills/learnharness-plugins/` is the plugin-authoring skill.

## Example data

`tests/fixtures/golden-data/` holds records written by the app: a teaching session that exercises every tool, a practice session on knowledge tracing, a graph from four imported notes files, five background-job records and the model settings.
