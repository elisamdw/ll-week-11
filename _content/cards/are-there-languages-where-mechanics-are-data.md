Marlon's first build names "a game generation tool potentially," and the week's inventory has 105 mechanics as rows. Researchers have written whole games as data for decades: Stanford's Game Description Language, VGDL, and Ludii's "ludemes." What do those languages model, and which of their ideas would a generator built on the LL's inventory need?

---

**Why the week needs it.** [A game generation tool](a-game-generation-tool.md) and [A game is data and a loop](a-game-is-data-and-a-loop.md) are open proposals; KB is gathering prior art for builds. The inventory in `_content/mechanics/` is a list, not a grammar, and these languages are the nearest thing to a grammar of mechanics.

**What would answer it.** For GDL, VGDL and Ludii: what a game file contains, how mechanics are expressed, what has been generated with them; whether any of them maps onto the inventory's mechanic IDs; one line on recent work generating games with language models.

**Where to look.** ludii.games and the Digital Ludeme Project papers (Browne, Piette), Stanford's General Game Playing course pages, the GVGAI framework (Perez-Liebana, Togelius), arXiv on LLM game generation.
