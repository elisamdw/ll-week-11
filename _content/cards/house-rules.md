**What it is.** Row 84 of the inventory, in "Designing and remixing" (TH, from Sicart's *Play Matters*): a rule invented during play becomes a new version of the game. The inventory also links Consalvo's *Cheating* and Kücklich's "Precarious Playbour", on players who bend games to their own ends.

**How it plays.** When the table argues about a rule, settle it, write it down, and name the new version. In the AI game the proposal is that Claude Code writes the table's change into a new ruleset file, so the starting versions stay intact.

**Where it is in the week.** House rules show up first by surprise: TD expects the table that gets furthest in the rules column of [Take apart a board game](take-apart-a-board-game.md) to find that half of what it wrote are house rules. Then on purpose: in William's [Remix one mechanic](remix-one-mechanic.md), the paper table writes its change as a house rule on a card while the other table has Claude Code make it. [Monopoly with live rents](monopoly-with-live-rents.md) turns the house-rule argument about rents into a dial.

**What it does for learning.** It shows that rules are made by players and can be remade, which is Sicart's point, and it gives a table's argument somewhere to go: a named version, playable next time. The inventory's note on AI: players govern the AI's rules the way they govern their own games.

**Which of Marlon's ideas it serves.**

> I don't need to build a UI for that designing or remixing. The UI is Claude code itself.

Marlon, Nov 14, in a voice chat with Claude, as transcribed in the handoff back to Claude Code (section 2). The inventory rewrote this mechanic's build after that chat: there is no editor, and students remix through Claude Code and the game's repo. CI's card [Claude Code is the UI](claude-code-is-the-ui.md) holds the idea.
