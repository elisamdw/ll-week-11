> Concern: Unity/Xcode means too many steps. Working in Claude Code, students see it immediately in the browser and iterate quickly.

Voice Claude's summary of Marlon's direction, Nov 14, voice session part 2 (about 14:12–16:51), posted as Process Black to #mk-work-in-progress. It came up while talking about AR and XR versions of the AI game.

The constraint is the loop time. A game engine and a phone build chain put minutes and a lot of setup between a change and seeing it; a web page reloads in a second. For a class of non-developers working through Claude, the short loop is the whole method: ask, look, ask again.

It decides what the AR experiments can be, as CI reads it. Voice Claude's notes in the same post: full WebXR and Web NFC don't work on iPhone, but camera-and-image AR in the browser (MindAR) does, tracking about two or three images at once. So the week's AR is image tracking in a web page, not an engine build. Marlon's answer to the limit is in [A phone reveals a card's secret](a-phone-reveals-a-cards-secret.md).

The LL's history fits: the realtime prototypes repo (`mk-realtime-prototypes`) was started in September to see how far web rebuilds of engine work can go.
