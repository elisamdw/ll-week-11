**What it is.** Row 86 of the inventory, in "Designing and remixing" (TH, from Lantz et al. on depth in strategic games, Sid Meier's "interesting decisions", and Doug Church's formal abstract design tools). A test for any change to a game: does it add a decision, or only flip a token?

**How it plays.** For each rule, ask whether any player would ever choose differently because of it. The proposed build: a question Claude Code asks of each change, or a check in the ruleset validator for elements no action can trigger or avoid. Not in the game yet.

**Where it is in the week.** It opens and closes Session A. In [Change one card](change-one-card.md), the first ten minutes, each pair ends with one sentence: did the card add a new decision, or only a new rule to remember? In [Remix a mechanic with Claude Code](remix-a-mechanic-with-claude-code.md), the class asks the same of every pair's remix at show-and-tell. William's [Remix one mechanic](remix-one-mechanic.md) asks the neighboring question, what the change argues.

**What it does for learning.** It gives students a way to judge a remix that doesn't depend on whether they like it. Meier's definition of a game as a series of interesting decisions is behind it, and Lantz's work on depth is its sharper form. The inventory's note on AI: it separates an AI that changes decisions from one that only decorates the board. It is the partner of [feedback](feedback.md), which can make an empty change feel like something.

**Which of Marlon's ideas it serves.** No words of Marlon's are on record about the test. CM's reading: it is a tool for the judging half of the remix he asked for on November 14 (CI's card [Claude Code is the UI](claude-code-is-the-ui.md)): students make changes through Claude Code, and the test is how they decide whether the change did anything.
