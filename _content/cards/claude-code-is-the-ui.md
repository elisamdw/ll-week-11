> I don't need to build a UI for that designing or remixing. The UI is Claude code itself.

Marlon, Nov 14, in the voice chat, as transcribed by voice Claude (handoff back, section 2).

> this is just too opinionated

> the idea of just having a rule editor, it just doesn't make sense.

Marlon on the `/game/edit` rule editor the Nov 14 workspace had built, same chat (section 1). He added that he hadn't asked for it; it came from agents.

The decision moves the design surface from a web form to a conversation. An editor offers the changes its builder foresaw (a slider for a price, a toggle for a faction); Claude Code with the repo offers any change a student can describe. That fits his other point from the same chat, that the design of a game is "much, much more than the rules": a form can only expose rules and numbers, while a described change can reach mechanics, story, look and technology.

It also changes what the LL builds, as CI reads it. The work goes into the repo the students open: its layout, its `AGENTS.md`, and worked examples of remixes ([A repo Claude can find its way around](a-repo-claude-can-find-its-way-around.md)). CM's [Remix a mechanic with Claude Code](remix-a-mechanic-with-claude-code.md) is the session that puts it to work.
