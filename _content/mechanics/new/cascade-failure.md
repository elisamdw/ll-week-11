# Cascading failure

## Definition

A failure in one part of a connected system spreads to the parts linked to it, so one shortage can bring down several; the more tightly linked the system, the further the failure spreads.

In one line (HI's row): "A shortage knocks a node down, and tightly coupled neighbors follow." [1]

## Description

Perrow calls failures of this kind, in tightly coupled systems, 'normal accidents'. [4]

In games:

- **[Pandemic](../games/pandemic.md)**: A city with three cubes that gets a fourth has an outbreak into every connected city, and an outbreak can set off another in a chain. [2]
- **[Data Center](../games/data-center.md)**: When the shared resources run short, a shortage adds a present harm. [3]

**Shows it** (HI's row): *Pandemic*'s outbreaks; Data Center's shortages [1]

**With AI** (HI's row): No one has to intend the harm; coupling turns a shortage into an outage. [1]

**In our game** (Nov 14 rulesets): yes: every version (shortages knock nodes down) [1]

## How to

**Try it in two minutes** (HI's row): Lay out cards in a line; when one fails, flip its neighbors unless someone pays to stop it. [1]

**Build it** (HI's row): Upkeep: if a resource runs short, a node next to the AI goes down (the engine's shortage rule). [1]

## Why to

**Proposed, for Marlon to choose:**

1. Show why infrastructure is political: what is linked to what decides who suffers.
2. Ask students to redraw the links to make the system less tightly coupled.

## Home game version

### In a regular classroom

**Proposed, for Marlon to choose:**

1. Dominoes or string between nodes on the map: knock one, see which follow.
2. Index-card nodes connected by yarn on the wall.

### Digitally

**Proposed, for Marlon to choose:**

1. A node graph where a failed node turns its neighbors yellow.
2. A spreadsheet in which one cell going to zero zeroes the cells that depend on it.
