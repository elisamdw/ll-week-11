# The move updates state

## Definition

A move is a small record of what one player did at one moment, and the game state is what you get by applying every move so far, in order, to the starting position. Sicart's definition of mechanics as methods that act on the game state is the reading behind it. [2][3]

In one line (EG's row): "A move is a small record of what a player did; the game state is every move so far applied, in order, to the start." [1]

## Description

ES's study 01 illustrates it with tic-tac-toe in which every click is a row and a slider unbuilds the board. [7]

In games:

- **[Chess](../games/chess.md)**: A game can be written down as its list of moves in notation, which lets a reader play through the game again. [4]
- **[Every tap is a row (prototype)](../games/proto-every-tap-is-a-row.md)**: Every tap writes a row, and the board is only those rows replayed. [5]
- **[Data Center](../games/data-center.md)**: Each AI card, vote and faction action changes the saved state, which the play page keeps in the browser. [6]

**Shows it** (EG's row): Chess notation (a game is its list of moves); ES's study 01; the LL's NFC taps [1]

**With AI** (EG's row): An AI player's move is one more row; reading the log is how a model catches up on a game. [1]

**In our game** (Nov 14 rulesets): yes: the play page logs each phase and action, and the state follows from them [1]

## How to

**Try it in two minutes** (EG's row): Play tic-tac-toe while one person writes each move on a card; then rebuild the board from the cards alone. [1]

**Build it** (EG's row): Store moves as rows in a log and compute the board from them; replaying part of the log shows the board at any earlier moment. [1]
