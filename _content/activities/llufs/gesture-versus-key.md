# One gesture, one move

1. **Demonstrate the starting point (5 min).** A volunteer shows one working MediaPipe launcher from last week. If none is available, sketch the gesture and use a human operator; label the exercise paper simulation.
2. **Choose the action (5 min).** Pick one action such as claiming a token. Write its starting state, permitted action and resulting state. Choose a key that does the same thing.
3. **Build or stage it (10 min).** In a staff-approved copy of the launcher, ask Claude Code to map one gesture to one action and a visible confirmation. One sustained gesture should yield one move; ask for a release before another move. Keep a key and reset available. Stay out of PL’s shared prototype folders.
4. **Compare (10 min).** Each partner tries five actions by gesture and five by key. Count intended moves, registered moves and unintended repeats. Swap roles; do not describe the counts as an accuracy benchmark across people.
5. **Choose the station path (5 min).** Keep the gesture only if players can tell what it does. Write one sentence about what embodiment adds and one limitation for the next host.

**What it teaches:** the difference between sensing a body and designing an action. Sicart frames the action’s relationship with state; MDA helps separate an input fault from a game experience. The gesture may be expressive even when a key is easier to operate.

**Prepare:** locate the existing launcher with staff; confirm camera permission and light; select a workspace copy before making changes. The Nov 10 recap establishes precedent, not a working asset path.

**Try it:** an LL laptop’s camera, a key and three paper tokens. No new electronics or purchases are required by this proposal.

**What could go wrong:** tracking drops, two hands trigger twice, or the camera sees a passerby. Narrow the interaction area, add visible armed/disarmed feedback, and return to the key when the gesture obscures play.
