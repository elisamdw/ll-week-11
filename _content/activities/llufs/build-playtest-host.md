# Build, playtest, host: an LLUF studio block

**LU’s proposed sequence, to place inside confirmed shifts:** no LLUF hours appear in W11/TIMELINE.md, and no fellow is assigned here. Wednesday’s class is Nov 18, 12:00–14:45; staff decides whether any part of this block happens before it. This session is not booked.

- **0–5 min:** confirm the available time, kit, current build and prototype choice. Read the research card’s distinction between last week’s precedent and this week’s untested assets.
- **5–30 min:** Playtest one change, report the evidence (25 min).
- **30–60 min:** The board and the log (30 min). Alternatively run A paper market with prices on a phone (30 min). If the pair chooses One gesture, one move (35 min), extend the block to 95 minutes or schedule it separately.
- **60–85 min:** Host it, reset it, hand it over (25 min).
- **85–90 min:** mark tested paths, unresolved faults and the next proposed action. Give AL the three-line handoff: artifact/route; evidence; what needs a decision.

**Outputs:** one setup/reset sheet, one observed playtest, a chosen input with a fallback, and one honest readiness label. Keep names and personal details out of the repo. A new observation sheet should separate the source of the claim from the interpretation and the next proposal.

**What it teaches and why:** fellows move between player, designer and host, comparing a mechanic’s intended effect with an observed experience (MDA), while attending to story, aesthetics and technology as well as mechanics (Schell).

**Prepare:** staff confirms shifts, station scope and class use; PL identifies the build and reset; another pair is available for handover. A 25-minute shift can do the playtest card alone and leave the remaining modules for another shift.

**Try it:** a laptop, a phone camera, paper and tokens at one table. Run with manual input first; use sensors only after the basic experience is legible.

**What could go wrong:** trying all three build options in one block, or calling a station ready because code exists. Choose one build option, and let the handover test determine the readiness label.
